# 情绪知了 · 本地加密版

本地运行的五步情绪日志网页：记录情境与情绪、识别认知扭曲、写下积极回应，再查看历史详情和趋势分析。日志内容保存在使用者自己的浏览器中，不上传到 GitHub。

## 交给 agent，一句话开始

复制以下提示词即可使用（需要固定版本时，也可以将仓库地址换为具体 commit 的链接）：

> 请下载并在我的本地电脑运行这个项目：https://github.com/apcg2/emotion-vault 。直接使用完整源码，保持原版 UI、功能、字段和交互，不重新设计或改写。根据 Windows 或 macOS 环境，按 README 安装依赖、启动并检查网页，告诉我访问地址和下次启动方式。保留本地加密和密码保护，不覆盖已有数据，不导入模拟记录，不部署到云端。需要授权或输入密码时由我操作；如果你只能访问云端容器，请先告知。

## 包含的功能

- 五步情绪日志与前后评分，认知扭曲的说明和示例。
- 首页周 / 月日历、按时间范围查看情绪分析。
- 历史记录列表、完整只读详情、二次确认删除；不支持编辑历史日志。
- 四位数字密码、本地加密与旧版数据迁移。
- 可选的 `/demo-data` 导入页：此前七天的模拟记录，明确标注、加密保存、避免重复导入。默认不会自动添加。

## Windows / macOS 使用

使用最新版 Chrome、Edge、Firefox 或 Safari，通过固定的 `http://localhost:3001/` 或 HTTPS 地址访问。加密由浏览器 Web Crypto 完成，不依赖 Windows 凭据管理器、Mac 钥匙串或某台电脑的文件路径。需要 Web Crypto、Web Locks 和可用的本地存储；不满足条件会提示错误，不会退回明文。

先下载或克隆本仓库，进入包含 `package.json` 的目录。已验证的运行环境为 Node.js 24.16.0 与 npm 11.13.0；`.nvmrc` 记录了该 Node 版本。Windows PowerShell / macOS 终端均可运行：

```sh
npm ci
npm run build
npm run start -- --port 3001
```

启动成功后打开 <http://localhost:3001/>，终端需保持运行。停止时在该终端按 Ctrl+C；下次在同一目录运行 `npm run start -- --port 3001` 即可。更新源码后重新安装依赖并构建。端口被其他程序占用时不要直接关闭它；更换端口会使用不同的浏览器数据空间。

这不是可双击的单文件 HTML。不要直接打开源码文件，也不要用普通 HTTP 局域网地址分发。只使用本机 localhost 服务，不需要 Cloudflare 登录、云数据库或 API 密钥。发布本仓库不等于将网页部署到公网。

## 密码与迁移

- 每个浏览器资料各自设置四位数字密码，没有统一默认密码。第一次写日志也需要先完成加密初始化；之后写新日志无需解锁。
- 打开历史或分析时验证密码；刷新、重新打开、从页面缓存恢复都会重新锁定。密钥和已解密内容不写入浏览器存储。
- 旧版用户使用原密码：读取并验证旧数据 → 加密 → 解密校验 → 写入完整密文并读回确认 → 删除旧明文及旧密码校验值。无需另设密码。
- 迁移失败、存储空间不足、密码错误或数据损坏时保留原数据。中途退出可在下次验证后继续清理。升级前请关闭其他旧版页面；旧页面新增的数据引发冲突时会停止迁移，不会自动覆盖。
- 密码遗忘后没有找回或重置入口。清除浏览器数据会丢失日志；本功能不提供备份或跨设备同步。不同用户若共用同一浏览器资料，也共用同一份加密日志；应使用独立系统账号或浏览器资料。

## 存储与安全边界

浏览器 localStorage 的 `moodflow_encrypted_vault_v1` 保存密文。迁移成功后移除 `moodflow_logs` 和 `moodflow_privacy_pin_v1`。地址、端口、浏览器或浏览器资料变化会看到不同的存储空间，不等于数据被删除。

每条完整日志以独立随机 AES-256-GCM 密钥和 96 位随机 IV 加密；AES 密钥通过 RSA-OAEP-2048 / SHA-256 公钥封装。RSA 私钥通过 PIN + 随机盐 + PBKDF2-SHA-256（600,000 次）派生的 AES-GCM 密钥加密。记录编号、公开日期和 vault 编号绑定为验证数据。公钥允许在未解锁时追加加密日志；解锁后的私钥只在内存中持有，导入为不可导出密钥。

首页日历仍显示记录日期和数量，因此这些元数据以及随机记录编号不是秘密；精确时间和正文、情绪、评分、认知扭曲、回应内容均在密文内。

四位数字只有 10,000 种组合，PBKDF2 只能拖慢离线穷举，不能提供强密码的安全性。本实现是基础隐私保护，不应承诺专业抗攻击能力。无法抵御已控制浏览器的扩展、恶意同源脚本、已解锁设备上的攻击、密文删除或整库回滚。删除旧存储键也不意味着安全擦除操作系统备份或浏览器数据库残留。面向公众正式发布前建议增加长密码选项、加密备份和独立安全评审。

## 验证

```sh
node --test test/privacy-pin.test.mjs test/encrypted-vault.test.mjs test/log-detail.test.mjs
npx tsc --noEmit --incremental false
npm run build
```

加密测试使用隔离的内存数据，不读取用户浏览器。涵盖正确/错误密码、Unicode 和长文本、多标签页写入锁、加密迁移、容量不足、中断恢复、迁移冲突、删除失败、篡改拒绝、重复初始化和旧格式验证。Windows / Safari 真机回归仍需在发布前完成；当前环境不能代替这些系统的实测。

兼容性参考：[Web Crypto](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto)、[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。
