# 情绪知了 · 双击 HTML 版

五步情绪日志：记录情境与情绪、识别认知扭曲、写下积极回应，再查看只读历史和趋势分析。保留原版 UI、字段、交互、四位密码和本地加密。

**使用者只需要一个 HTML 文件和浏览器，不需要 Node.js、安装依赖、终端或服务器。** 完整 React / TypeScript 源码仍保留供开发者维护。

## 下载与打开（Windows / macOS）

1. [下载 emotion-vault.html 成品](https://github.com/apcg2/emotion-vault/releases/latest/download/emotion-vault.html)，保存到电脑上的固定文件夹。也可到 [Releases](https://github.com/apcg2/emotion-vault/releases)，在 Assets 中选择同名文件。
2. 双击 `emotion-vault.html`，或右键选择用最新版 Chrome / Edge 打开。**不要选择 GitHub 自动生成的 Source code ZIP，也不要把源码 index.html 当成成品。**
3. 首次使用时自己设置四位数字密码。以后仍双击同一个文件，保持相同浏览器及浏览器资料；无需 agent。

成品已内嵌代码、样式、图标和图表库，没有 CDN、在线字体、业务 API 或遥测请求，下载后可离线使用。建议固定文件位置，创建快捷方式 / 替身，不频繁移动或改名。

所用开源组件的版权和许可证文本也内嵌在 HTML 的 `third-party-notices` 区域，不影响页面显示；分发时请保留。

浏览器须允许 JavaScript、本地存储、Web Crypto 和 Web Locks。无法安全加密或加锁时停止操作，不退回明文或不安全的写入方式。Firefox / Safari 的本地文件存储行为尚未完成人工验证；不保证所有浏览器或受管设备策略下都可用。不要关闭浏览器安全限制。

## 重要：日志不在 HTML 文件里

HTML 是程序，日志密文仍在**当前浏览器的本地存储**。复制 HTML 到另一台电脑不会带走日志，也不会将日志上传到 GitHub。

- 定期点击首页 **“备份与恢复 → 下载加密备份”**，把 JSON 文件另存到安全位置。备份包含密文和日历日期等元数据，不含明文日志或密码；恢复需原密码。请确认文件实际下载成功。
- 换电脑、换浏览器、移动文件或更新 HTML 前先备份。恢复时，在空白浏览器环境打开 HTML，直接进入“备份与恢复”，选择备份、输入原密码，**无需先设置新密码**。
- 恢复先验证格式、原密码和全部记录，再一次性保存。当前已有日志库、旧数据或密码时拒绝覆盖，不自动合并或清空。请使用未使用过的独立浏览器资料恢复，不要删除原数据。
- 无痕模式、清理浏览器数据或丢失浏览器资料可能丢失日志。备份失败时保留当前页面。
- 不同浏览器对 `file://` 存储的处理不统一，文件路径变化也可能出现空白记录，不代表原数据已被删除。请尝试原文件路径和原浏览器，或恢复备份。见 [MDN localStorage 说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage#description)。

密码遗忘后没有找回入口。四位数字仅 10,000 种组合，只适合基础隐私保护，不能抵御专业离线穷举；加密备份也应妥善保管。

## 从旧 localhost 版迁移

`http://localhost:3001/` 与本地 HTML **不共享存储**。不要清理旧浏览器数据，不要因新页面空白而认为旧数据丢了。

1. 在原电脑、原浏览器资料中，用当前源码临时打开带备份功能的旧地址。先在原终端用 Ctrl+C 停止旧服务；更新源码后在项目目录运行 `npm ci`、`npm run dev`，访问 **http://localhost:3001/**。这一步只为旧用户导出一次，不是 HTML 日常使用要求。不要换成 127.0.0.1 或其他端口。
2. 首页点击“备份与恢复”，下载加密备份。若提示旧版明文迁移未完成，由本人先进入历史记录输入原密码，完成迁移后再下载。不要把密码或日志交给 agent。
3. 打开下载的 HTML，点击“备份与恢复”，选择备份并输入原密码。新环境已有数据时不会覆盖，请另用空白浏览器资料。
4. 确认历史和分析无误、保存好备份，再关闭旧服务。以后只打开 HTML。导入不会删除原 localhost 数据。

## 功能

- 原有五步情绪日志、前后评分、认知扭曲说明和示例、积极回应及相信程度。
- 首页周 / 月日历、按时间范围查看趋势分析。
- 历史列表、完整只读详情、二次确认删除；不支持编辑历史。
- 四位数字密码与本地加密；刷新、重开、从页面缓存恢复后，查看历史或分析需重新验证。
- 加密备份与空白环境恢复；无跨设备自动同步。
- 可选模拟数据页：地址末尾添加 `#demo-data`，用户手动确认才导入此前七天的明确标注数据。默认不添加。

若 agent 安装源码依赖遇到 `CODEBUDDY_BROKER_DENY` 或权限拒绝：确认项目目录，申请正式授权；仍被拒绝则停止重试，由用户在系统终端完成。不要停用或绕过代理、shim、沙箱。**普通使用者下载 HTML 即可，不会进入依赖安装流程。**

## 加密与安全边界

沿用旧 `moodflow_encrypted_vault_v1` 格式。每条完整日志使用独立随机 AES-256-GCM 密钥及 96 位 IV；AES 密钥由 RSA-OAEP-2048 / SHA-256 公钥封装。RSA 私钥由 PIN + 随机盐 + PBKDF2-SHA-256（600,000 次）派生的 AES-GCM 密钥加密。公钥允许锁定时写新日志；解锁私钥不可导出，仅在内存中保留。

正文、精确时间、情绪和评分、认知扭曲及回应均加密。日历日期、数量和随机编号是公开元数据。Web Locks 串行协调共享同一存储的页面写入；失败时停止，不做不安全的后备加锁。

旧明文迁移在验证 PIN、加密、解密校验、保存读回确认后才移除 `moodflow_logs` 和旧 `moodflow_privacy_pin_v1`。备份不导出旧明文；恢复仅接受本应用带版本的加密备份，密码错误、篡改、取消或容量不足时不清空当前数据。

无法抵御已控制浏览器的扩展、恶意代码、已解锁设备上的攻击、密文删除或整库回滚。删除存储键不等于安全擦除磁盘或系统备份。仍建议后续增加长密码和独立安全评审。

## 验证范围

`npm test` 使用合成数据和内存存储，不访问真实浏览器日志。覆盖加密/解密、迁移、并发写入、篡改和容量失败、只读详情、备份恢复/取消/覆盖拒绝，以及中文和空格路径下的单文件打包。`npm run build` 先做类型检查，再输出 HTML。

[Windows / macOS 自动化检查](https://github.com/apcg2/emotion-vault/actions/workflows/windows.yml) 在两个系统分别安装、测试和构建；不等于桌面双击或所有浏览器均已通过。

人工验收：双击 HTML → 在空白环境设置测试 PIN → 保存测试日志 → 查看只读详情和分析 → 关闭重开确认重新锁定 → 下载备份 → 在另一个空白浏览器资料恢复 → 删除测试记录并重开确认。全程使用合成内容，不在真实数据环境清空或重置存储。
